# Plan Document Assessment (PDA) — Business Requirements

**Checklist data:** `data/plan_document_assessment.json` (gitignored, local only) — 13 sections, 160 topics.

## What this assessment is

A **Plan Document Assessment (PDA)** reviews a self-funded employer health plan's **Plan Document / Summary Plan Description (SPD)** against a fixed checklist of known compliance, drafting, and risk topics — regulatory requirements (ERISA, ACA, MHPAEA, NSA, HIPAA, COBRA, etc.), plan-drafting best practices, and commonly-missing protective language (exclusions, definitions). It answers, topic by topic: **is the Plan Document compliant, non-compliant, or is there not enough information to tell?**

**Input document(s):** the Plan Document / SPD (PDF). No other document is required.

**Output:** one finding per checklist topic (see `cross-cutting-business-rules.md` for the shared finding shape), plus a formatted Word report.

## Compliance status model

Every ordinary topic (i.e. not one of the two roll-up sections below) is assessed against three possible outcomes:

| Status | Meaning | Report treatment |
|---|---|---|
| **Compliant — Yes** | The Plan Document contains language satisfying the topic's requirement | No action required |
| **Compliant — No** | The Plan Document's language is missing, contradicts, or fails the requirement | Flagged finding — quoted language (or its absence), why it matters, and a suggestion |
| **Compliant — Not Sure** | The Plan Document has no information at all on the topic, or a genuinely optional topic doesn't apply | Routed for human review rather than guessed |

Each finding must be **evidence-grounded**: a verdict of Yes/No requires a verbatim quote from the Plan Document (or an explicit statement that the language is absent) — a business rule that exists specifically to prevent unsupported/hallucinated compliance verdicts.

## Two special roll-up sections (presence-check, not compliance-check)

**Missing Exclusions** and **Missing Definitions** are evaluated differently from every other section: instead of a per-topic Compliant Yes/No/Not Sure judgment, the assessment does a single **inventory check** — which of these standard exclusions/definitions does the Plan actually contain, and which are genuinely absent? The rule: a topic counts as *present* if the Plan covers the same concept even under different wording (synonyms/near-equivalents count) — it's only *missing* if no relevant language exists anywhere in the designated section. The output rolls up into one shared finding per section ("the Plan is missing: X, Y, Z") rather than one finding per topic. The ordinary **Definitions** section (distinct from **Missing Definitions**) is still evaluated topic-by-topic like any other section.
