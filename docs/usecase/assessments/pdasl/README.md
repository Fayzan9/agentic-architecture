# Targeted Stop Loss Review (PDASL) — Business Requirements

**Checklist data:** `data/targeted_stop_loss_review.json` (gitignored, local only).

## What this assessment is

The **Targeted Stop Loss Review (PDASL)** is an **add-on to the PDA**, not a standalone product: it runs the same reviewer against a curated list of topics known to commonly create a mismatch between what the **Plan Document** covers/pays and what the employer's **Stop Loss Policy** will actually reimburse. Where the PDA asks "is the Plan compliant on its own terms," PDASL asks "could this specific topic cause the Plan to pay a claim that the Stop Loss carrier won't fully reimburse?"

**Input documents:** the Plan Document / SPD **and** the Stop Loss Policy (both required — this is a two-document comparison, unlike the base PDA).

**Compliance status model:** same three-way Compliant Yes/No/Not Sure outcome as the PDA (see `../pda/README.md`), but the judgment is based on comparing language **in both documents** rather than the Plan alone — `Contains_Information` is "Yes" if *either* document has relevant language, and a verdict of "Not Sure" applies only if **both** are silent on the topic.

## Notes

- The source JSON contains a `Test - LULU` section (0 topics) and two junk topics (`test`, `Test_LULU`) that are clearly test/scratch data, not real business content — excluded from the list above, but worth cleaning up in the source data since a future agent reading this checklist directly would otherwise ingest them as real topics.
- Several topics here overlap conceptually with the **Stop Loss Gap Review (SLGR)** checklist (e.g. Medical Necessity, Experimental/Investigational, Workers' Compensation) — PDASL and SLGR are two different product surfaces over a related problem (Plan vs. Policy mismatch); see `cross-cutting-business-rules.md` for how they differ in scope and audience.
